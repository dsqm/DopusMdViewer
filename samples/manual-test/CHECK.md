```

## 十七、打开方式改走 Opus 查看器（`16-open-in-opus-viewer.md`，2026-11-04）

### 为什么是命令行

Viewer Plugin SDK 里没有「让 Opus 打开某个文件」的接口——`DVP_InitEx` 只给消息窗口句柄、
版本号和语言名，`plugin support.h` 的 OpusFunctions 也没有 RunCommand 一类函数。Opus 对外
只有 `dopusrt.exe /show "<文件>"` 这一条路（`d8viewer.exe` 是同类旧入口）。插件起一个
dopusrt 就返回，不等它：dopusrt 把文件转交给 Opus 后自己就退了。

### 前置（三条都做完再测）

1. `build.bat` 产出 `bin\DopusMdViewer.dll` 与 `bin\DopusMdViewer\`；
2. 跑 `..\install-DopusMdViewer.bat`，把 DLL 与 `web\` 装进 `Viewers\`；
3. **完全重启 Opus**——Opus 只在启动时扫描 `Viewers\`。替换时旧 DLL 会被改名移出
   （Windows 允许改名已映射的映像），但正在跑的进程不会换成新映像。

确认跑的是新版本：设置窗口 → 高级页 →「版本」、`bin\DopusMdViewer.dll` 属性页的
「文件版本」、日志首行 `DLL: …` 报出的版本，三处一致（都取构建时生成的 VERSIONINFO；
日志里的文件时间只是辅助线索，复制/安装会改写它）。对不上就是旧映像
（Opus 只在启动时扫描 `Viewers\`），后面几条都不作数。

- **菜单里没有「在 Opus 查看器中打开」**：`UtilOpusViewerExe()` 没找到 `dopusrt.exe`。
  查找顺序是「宿主 exe 同目录 → DLL 的上级目录 → `%ProgramFiles%\GPSoftware\Directory Opus`」，
  三条都不中才不出现（便携版被挪走、dopusrt 被改名都会走到这里）。
- **点了没反应、日志也没有新行**：任务管理器看有没有起 `dopusrt.exe`。没有就是
  `CreateProcessW` 失败（权限或安全软件拦截）。
- **弹了 Opus 的「无法显示此文件」**：这个扩展名在名单里但 Opus 其实看不了。点
  「扩展名名单…」把它删掉即可，不用改代码。
- **日志开关的位置**：设置 → 高级 → 「记录日志」；日志目录用同页的「打开日志目录」。
  默认关闭，测完记得关掉。

### 已知限制（不算失败）

- 内置名单按 Opus 自带插件整理（图片 / RAW / JPEG2000 / PCX / TGA / 文本 / Office / 影音 / PDF）。
  第三方查看器插件带来的新扩展名要自己在「扩展名名单…」里加；名单留空表示沿用内置。
- 远程图片没有磁盘路径，不给 Opus 查看器项（插件不把网络图悄悄落盘）。
- 每次点击起一个 `dopusrt.exe` 进程（毫秒级，转手后即退出），不做常驻。
- **不开放自定义命令行**：`dopusrt.exe` 能「打开一个文件」的开关只有 `/show`，它后面
  没有可调参数；独立查看器的行为（自动调整大小、居中、幻灯片、边框）在 Opus 自己的
  「配置 → 查看器」页里。`/vcmd Show VIEWERCMD=…` 是给已打开的查看器发命令，不是打开文件。
  换第三方看图程序用图片右键的「打开方式」，或把链接开关关掉走系统默认程序。
